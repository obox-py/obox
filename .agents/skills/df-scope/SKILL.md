---
name: df-scope
description: 依据 task.md 的涉及文件与用户确认，产出本次变更的执行边界 scope.md——可改白名单、明确不动、越界处置。只写这一份文件。
---

df-scope 产出一份文件：@`{df_change_dir}/scope.md`@。它定义**执行时允许动哪里**，供执行与评审阶段逐文件比对。不写代码，不改任务清单，不推进 @`df_stage`@。

## 变量

| 变量 | 用途 | 说明 |
|---|---|---|
| @`df_proj_dir`@ | 工程根 | 重要!!，禁止丢弃 |
| @`df_us_id`@ | 本次变更编号 | 重要!!，禁止丢弃 |
| @`df_change_dir`@ | @`{df_proj_dir}/codespec/changes/{df_us_id}`@，scope.md 落点 | - |

变量缺失时先跑一次 @`df-env`@ 补齐。

## 步骤

### 1. 读输入

| 文件 | 用途 | 缺失时 |
|---|---|---|
| @`{df_change_dir}/task.md`@ | 任务清单，白名单的唯一依据 | **停手**：没有任务就无从划边界 |
| `{df_change_dir}/delta-spec.md` | 需求口径，判断某文件是否真的该动 | 可跳过 |
| `{df_change_dir}/delta-design.md`、`delta-arch.md` | 改动落点与受影响模块；白名单必须覆盖它们提到的模块 | 可跳过（仅提示） |

### 2. 汇总白名单

把 @`task.md`@ 每行的「涉及文件 / 模块」抽出、去重、写成 glob：

- 目录级改动写 @`src/api/export/**`@，单文件写全路径
- 同一模块被多条任务涉及，合并成一条
- **一条都不许漏**：任务里出现而白名单里没有，执行阶段就会被判越界

### 3. 划出「明确不动」

即使本次用不上，也要挡住的区域：公共接口与核心模块、依赖锁文件、生成物、以及本次明显不该碰的其他模块。

### 4. 与用户确认

白名单直接决定执行阶段能改什么，必须让用户点头（提问只用 AskUserQuestion）：

```js
AskUserQuestion({
  "questions": [
    {
      "header": "执行边界（也可直接输入要加或要挡的路径）",
      "question": "本次允许改这些：<白名单>；这些一律不动：<不动清单>。对吗？",
      "options": [
        {"label": "对，就按这个边界", "description": "写入 scope.md"},
        {"label": "白名单要收窄", "description": "我按你的输入删掉多余项"},
        {"label": "不动清单要加项", "description": "我按你的输入补上"}
      ],
      "multiSelect": false
    }
  ]
})
```

用户没明确确认之前不许落盘。

### 5. 写 scope.md

按 @`templates/scope.md`@ 填，落盘到 @`{df_change_dir}/scope.md`@：

- @`## 可改（白名单）`@ 一行一条 glob
- @`## 明确不动`@ 一行一条；与白名单冲突时以白名单为准，并说明为什么
- @`## 越界处置`@ 保留固定措辞：停手、报「需要改 X 因为 Y 对应 Z 需求」、确认后才扩
- 模板里的 @`<...>`@ 与注释全部替换；frontmatter @`status`@ 改成 @`done`@

### 6. 回读校验

- @`task.md`@ 每一行的「涉及文件」都能被白名单某个 glob 命中，一条不漏
- 白名单与「明确不动」没有交集
- 三节齐全，无占位符残留

校验不过就回头补，不许带着漏洞落盘——执行阶段会按它拦人，边界写错等于假拦。

### 7. 简报与确认

简报（不超过 8 行）写进下面提问卡的 `question`：白名单几条、不动几条、覆盖了哪几个任务的涉及文件、有没有需要用户再定的歧义。然后提一题：

```js
AskUserQuestion({
  "questions": [
    {
      "header": "验收（要改什么就直接输入）",
      "question": "【简报：结论 / 证据 / 风险，不超过 8 行】\n\n这份执行边界符合你的要求吗？不符合就直接输入要改的地方。",
      "options": [
        {"label": "符合", "description": "scope.md 定稿"}
      ],
      "multiSelect": false
    }
  ]
})
```

- 只有两类回答：@`符合`@，或用户直接输入修改意见
- 用户输入 → 按意见改 → 重新出简报 → 再问一次
- **迭代上限 3 轮**；到顶列出未达成项并停手

## 边界

- **只写 @`{df_change_dir}/scope.md`@**：不改 @`task.md`@（发现任务越界就报给用户，让他回改任务）、不写 spec/design/delta/validation/review。
- **不写代码**，**不推进 @`df_stage`@**。
- **不许自行收窄或放宽**：白名单必须来自 @`task.md`@ 与用户确认，不是你自己判断"大概就这些"。
- **提问只用 AskUserQuestion**。
- **宿主没有 AskUserQuestion 时**：退回编号列表提问，不跳过提问。
