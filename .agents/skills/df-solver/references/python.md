# Python 代码规范与坏味道

## 规范

- 命名：模块与函数 `snake_case`、类 `PascalCase`、常量 `UPPER_SNAKE`
- 类型标注：公共函数写参数与返回值类型；`Optional`/`|` 写清可为空
- 不可变默认值：默认参数不用可变对象
- 异常：捕获具体异常；自定义异常继承合适的基类
- 资源：`with` 管理文件与连接
- 导入：不用 `from x import *`；避免循环导入（拆模块或延迟导入）
- 副作用：模块导入时不做 I/O 与网络请求

## 坏味道

| 坏味道 | 识别信号 | 改法 |
|---|---|---|
| 可变默认参数 | `def f(x=[])` | 默认 `None`，函数体内新建 |
| 裸 `except` | `except:` / `except Exception: pass` | 捕获具体类型并处理 |
| 误用可变全局 | 模块级 list/dict 被函数修改 | 改成显式参数或类状态 |
| 隐式 `None` 返回 | 有时返回有时不返回 | 统一返回类型 |
| 过宽类型 | 全篇 `Any` / 无标注 | 补标注，缩小 `Any` 范围 |
| 手写循环代替推导 | 建 list 只靠 `append` | 列表/字典推导 |
| `==` 比较 `None` 以外的怪写法 | `if x == True` | `if x` |
| 深嵌套 `try/else/finally` | 三层以上 | 提前返回，拆函数 |
| 字符串拼 SQL | f-string 进 `execute` | 参数化查询 |
| 异步里调同步阻塞 | `async def` 里 `requests.get` | 换异步客户端或 `run_in_executor` |
| 单文件上千行 | 一个 `.py` 承担多个职责 | 按领域拆包 |

## 特别注意

- 修改的数据结构会被外部持有引用：返回副本或文档说明所有权。
- 浮点数金额、时间时区、编码（始终显式 `encoding="utf-8"`）是三类高发 bug。
