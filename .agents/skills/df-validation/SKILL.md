---
name: df-validation
description: 检查一条 US 变更的全部文档，找出文件内与文件间的遗漏、冲突和无法实现的问题，按严重/一般/建议分档，与用户确认修复范围后迭代收敛。只改文档，不碰代码。
---

df-validation 只做一件事：**在动手实现之前，把文档里的坑挖出来并修掉**。它不改项目代码，不跑构建，不动基线。

## 变量

| 变量 | 用途 | 说明 |
|---|---|---|
| `df_proj_dir` | 工程根 | 重要!!，禁止丢弃 |
| `df_us_id` | 本次变更编号 | 重要!!，禁止丢弃 |
| `df_spec_dir` | `{df_proj_dir}/codespec/specs`，基线所在 | - |
| `df_change_dir` | `{df_proj_dir}/codespec/changes/{df_us_id}`，delta 与 task 所在 | - |

变量缺失时先跑一次 `df-env` 补齐。

## 步骤

### 1. 收齐待检文件

| 文件 | 缺失时 |
|---|---|
| 基线 spec（`specs/spec.md` 或 `specs/<capability>/spec.md`）、`{df_spec_dir}/design.md` | 停手：基线不全，检查没有参照 |
| `{df_change_dir}/proposal.md`、`delta-spec.md`、`delta-design.md`、`task.md` | 停手：指出缺哪份，先补齐再检 |
| `{df_change_dir}/delta-arch.md`、`{df_proj_dir}/README.md` | 增量架构分析与项目门面；缺了说明对应阶段没跑完，先补齐 |

`{df_change_dir}/validation.md` 若已存在，读进来：本次是**追加轮次**，不是重写历史结论。

### 2. 先跑结构校验，再找语义问题

结构问题不靠眼睛看，跑脚本：

```bash
python "<本 skill 目录>/scripts/check.py" --proj "{df_proj_dir}" --us "{df_us_id}"
```

输出 JSON，`issues[]` 每条带 `level` / `code` / `file` / `line`，退出码非 0 表示存在严重项。脚本查的是机械可判定项：小节齐备、每条需求有场景且场景含 WHEN/THEN、delta 小节名合法、`MODIFIED`/`REMOVED` 的条目名能在基线找到、任务覆盖每条需求、任务方式与状态取值合法、依赖无环、围栏闭合、无占位符残留。

- `严重` 项**直接并入问题清单**，不必再判断真伪
- `一般` 项由你决定是否入清单
- 脚本覆盖不到的（互相矛盾、无法实现、命名漂移）才由下面三个维度补

**遗漏**
- **proposal 的需求草案有哪条没被 delta-spec 覆盖**（这是最容易被漏掉的跨文件遗漏）
- 某条 delta 需求没有任何任务覆盖
- 某条需求没有 `#### Scenario:`，或有场景但没有可观测结果
- design 里的组件、接口在代码里根本不存在（要实读确认）
- 任务没有完成判据，或判据无法验证

**冲突**
- delta-spec 与基线 spec 的同名需求互相矛盾
- delta-design 的依赖方向与基线 design 相反
- 几条任务的 `涉及文件` 重叠又互相无依赖，顺序不明
- 术语、命名、错误码在不同文件里不一致

**无法实现**
- 引用了代码中不存在的模块、类型、命令
- 任务依赖的组件在本次被 `REMOVED` 或改名
- 依赖图里有环
- 判据要求的能力超出当前技术栈

每条问题必须写清四件事：**档位、位置（文件:行 或章节）、证据（原文引用）、影响**。没有证据的判断不要写进清单——那是猜测，不是检查结果。

### 3. 分档

| 档位 | 判据 | 例子 |
|---|---|---|
| **严重** | 按当前文档实现一定会做错或做不出来 | 需求互相矛盾、需求无任何任务覆盖、引用不存在的模块、依赖有环 |
| **一般** | 会导致返工或歧义，但能实现 | 判据模糊、边界没定、术语不一致、任务粒度失衡 |
| **建议** | 优化项，不改也能实现 | 任务顺序可更省、措辞可更清楚 |

### 4. 报告并确认修复范围

先把清单摆给用户（表格：档位 / 位置 / 问题 / 证据），再提一题：

```js
AskUserQuestion({
  "questions": [
    {
      "header": "修复范围（也可直接输入你的处理方案）",
      "question": "共 <N> 项（严重 <a> / 一般 <b> / 建议 <c>）。这轮修哪些？",
      "options": [
        {"label": "只修严重 (Recommended)", "description": "先把会做错或做不出来的档住，一般与建议留到下一轮"},
        {"label": "全部修复", "description": "一次性清干净，改动面最大，可能改到已定稿的内容"},
        {"label": "暂不修复，仅记录", "description": "只写进 validation.md，带病进入实现"}
      ],
      "multiSelect": false
    }
  ]
})
```

用户自己给方案时，按他的方案执行，不要擅自扩大范围。

### 5. 修复

**只能改这三份**：`delta-spec.md`、`delta-design.md`、`task.md`。

- **基线 `spec.md` / `design.md` 不许改**：基线问题属于基线创建与补正那一步。发现了就记进 validation.md，处理列写"需上游修正"，不自己动手。
- 改完后逐条在问题清单里更新状态：`已修复` / `待验证` / `待用户决策` / `需上游修正` / `不修复`
- **`已修复` 必须附复核证据**：重跑 `check.py` 的对应输出行，或指明改动了哪个文件的哪几行；没有证据的只能标 `待验证`，不许直接写"已修复"
- 修复不得引入新占位符，也不得删掉用户已定稿的内容

### 6. 迭代收敛

修完重跑第 2 步的分析（不是重读旧结论）：

- 无新增问题，或只剩"建议"档 → 停止，写 `## 处理记录` 收尾
- 仍有严重问题 → 回到第 4 步再确认一次
- **轮数上限 3 轮**：到顶还在反复，就把争议点写成待决策项交回用户，不再自行迭代

### 7. 写 validation.md

按 `templates/validation.md` 填，落盘到 `{df_change_dir}/validation.md`：

- `## 检查范围` 列出五份文件的结论
- `## 问题清单` 一行一项，`档位` 只取 `严重` / `一般` / `建议`
- `## 处理记录` 每轮一条，写清修了什么、谁决定的
- `## 遗留` 只放需要产出方修正、或在实现阶段确认的条目
- frontmatter `status`：本轮确认无严重问题才改成 `done`，否则保持 `draft`

### 8. 简报与确认

收尾前写一段简报（不超过 8 行），直接放进下面提问卡的 `question`，不要另起一段。简报至少包含：

- 落盘路径：`validation.md`
- 问题总数与分档（严重 / 一般 / 建议）；本轮修了哪些
- 每条 `已修复` 的证据来源（`check.py` 行号或 `文件:行`），以及仍 `待验证` 的有几条
- 遗留几条，分别归谁处理（本 skill / 产出方修正 / 实现阶段）
- `status` 是 `done` 还是仍为 `draft`，以及原因

```js
AskUserQuestion({
  "questions": [
    {
      "header": "验收（要改什么就直接输入）",
      "question": "【简报：结论 / 证据 / 风险，不超过 8 行】\n\n符合你的要求吗？不符合就直接输入要改的地方。",
      "options": [
        {"label": "符合", "description": "validation.md 定稿，可以进入实现"}
      ],
      "multiSelect": false
    }
  ]
})
```

- 只有两类回答：`符合`，或用户直接输入修改意见
- 用户输入 → 按意见改 → 重新出简报 → 再问一次
- **迭代上限 3 轮**；到顶仍未确认，列出未达成项并停手，不再自行修改

## 边界

- **只改文档，不碰代码**：不写源码、不改配置、不跑构建、不建分支。
- **只改 `delta-spec.md` / `delta-design.md` / `task.md` / `validation.md`**：基线永远不碰。
- **不擅自扩大修复范围**：用户选了只修严重，就不许顺手改一般。
- **不推进 `df_stage`**。
- **提问只用 AskUserQuestion**。
- **宿主没有 AskUserQuestion 时**：退回编号列表提问，不跳过提问。
