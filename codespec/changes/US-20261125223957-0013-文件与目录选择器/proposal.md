# 文件与目录选择器 · 本地与 SSH 的 Win11 风格对话框

## 背景

扩展目前只能用 Input 手填路径，没有选择文件/目录的能力。需要一套 obox API：扩展发起选择请求，obox 弹出仿 Win11 的对话框，支持本地与 SSH 远端（Windows、Linux）浏览；对话框只阻塞发起它的窗口，结果异步回给扩展。

## 目标

- 新消息 PICKER_OPEN / PICKER_RESULT：类型（文件/目录）、后缀过滤、多选、标题、起始路径、可选 SSH 连接参数
- 对话框仿 Win11：左侧快速访问、面包屑、搜索、详细信息列表、类型过滤、多选、确定/取消
- 本地与 SSH 远端（paramiko，密码或私钥）都能浏览、进入目录、选择；远端结果返回远端路径
- 对话框只对发起窗口模态：主窗口发起阻塞主窗口，子窗口发起只阻塞该子窗口，其它窗口不受影响
- 浏览与远端 I/O 在后台线程，界面不冻结，结果异步投递

## 范围

**做：**

- 新增 PICKER_OPEN / PICKER_RESULT 消息与扩展侧调用方式（context.request 异步等待）
- 新的选择器对话框与本地文件系统浏览、过滤、多选、快速访问
- paramiko 接入：连接、列目录、默认目录、主机指纹确认；密码/私钥由调用参数传
- 发起窗口判定与按窗口模态
- 测试、verify 场景、扩展开发文档

**不做：**

- 不做远端文件上传/删除/重命名（只浏览与选择）
- 不做凭据持久化（参数传入，不落盘）
- 不做多标签页/多窗口同时浏览不同远端
- 不改现有 Input 组件

## 需求草案

1. 扩展发 PICKER_OPEN，带模式（file/dir）、扩展名列表、多选、标题、起始路径、可选 SSH 参数；obox 校验后打开对话框
2. 对话框左侧为快速访问（桌面、下载、文档、图片、此电脑；SSH 连接入口），中间为面包屑与搜索，右侧为详细信息列表（名称、修改时间、类型、大小）
3. 文件模式按扩展名过滤，目录模式只列目录；多选时返回全部选中项
4. 本地路径返回绝对路径；SSH 结果返回远端路径与连接标识（host、user）
5. SSH 参数由调用方提供：host、port、user、password 或 key_path/passphrase；首次连接需确认主机指纹
6. 对话框对发起窗口模态：主窗口发起时阻塞主窗口；App 子窗口发起时只阻塞该子窗口
7. 目录枚举与 SSH 操作在后台线程执行，界面保持响应；加载中显示占位与错误信息
8. 取消或关闭返回空结果；错误以 PICKER_RESULT 的 error 字段带回
9. 对话框沿用 docs/UI.md 的字号、间距与配色，深浅主题一致

## 关键取舍

- paramiko 作为运行时依赖：换来稳定的 SFTP 与跨平台一致的错误处理；不做系统 sftp 解析
- 凭据只走参数：不在宿主落盘；对话框内可再次输入密码以便重连
- 模态按窗口：Qt.WindowModal + 发起窗口为父；主窗口发起自然阻塞主窗口
- 远端结果不自动下载：返回远端路径，避免大文件隐式传输；需要内容由扩展自行处理（后续可加下载选项）
- 浏览走后台线程：本地也统一异步，避免网络盘卡住 UI

## 与基线的冲突

- 基线没有文件选择类 API，需 ADDED 一条「文件与目录选择器」
- 基线「消息基类与广播语义」不变，新增的是消息类型
- 基线「依赖」只有 PySide6 与 matplotlib，本次加 paramiko，需在构建与安装包里带上
- 基线「对话框风格」需补选择器的 Win11 视觉规格

## 假设

- SSH 使用 paramiko；Windows 与 Linux 远端同样走 SFTP
- 发起窗口由消息里的 window_id 指定；缺省为主窗口
- 目录模式的 SSH 结果同样返回远端路径
- 首版只做浏览与选择，不做上传下载
