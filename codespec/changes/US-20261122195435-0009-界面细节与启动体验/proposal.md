# 界面细节与启动体验 · 设置只读、切换保位、图标与对比度

## 背景

八条来自实际使用：设置里的版本号显示成可编辑输入框；切换语言或主题后视图被重建回首页，用户正在调的设置页丢失；启动后的默认落点不清；任务栏显示的是 Python 图标；light 主题的滑块轨道几乎看不见；标题栏三个窗口按钮在两套主题下对比度不足；托盘右键菜单只有三项、观感单薄，想照豆包的托盘菜单重新设计。

## 目标

- 版本号只读展示，不再是输入框
- 切语言与切主题后仍停在原视图与原设置分类
- 启动落点明确且可预期
- 任务栏显示 obox 图标
- 托盘右键菜单有清晰的分组与层级，观感接近豆包
- light 滑块轨道与标题栏三按钮在两套主题下都清楚可辨

## 范围

**做：**

- 设置贡献新增只读的 label 类型，宿主把版本项改成 label，设置页按类型渲染 Text
- switch_language 与 switch_theme 重建前记下当前视图与设置页分类，重建后恢复
- 启动默认视图按确认结果固定，不依赖扩展注册顺序的副作用
- Windows 上设置进程级 AppUserModelID 并给 QApplication 设窗口图标，安装器同步 exe 图标
- 托盘菜单改成分组菜单：打开 obox 窗口 ‖ 切换主题 / 切换语言 / 刷新扩展 / 打开扩展目录 ‖ 设置 / 退出，分隔线、行高与悬停态跟主题一致，主题与语言为可勾选子菜单
- light 滑块轨道换成可辨的中性色；标题栏三按钮颜色与悬停底色按主题对比度重定
- 两套主题同步，截图比对

**不做：**

- 不改设置页布局结构（左侧分类 + 右侧条目）
- 不做托盘菜单自绘动画与自定义图标字体
- 不改扩展打包产物结构（只换图标资源）
- 不引入新的第三方依赖

## 需求草案

1. 设置里的版本项以只读文本呈现，不可编辑、不可聚焦；扩展配置同样可用只读项
2. 切语言后仍停在切换前的视图；若在设置页，分类也保持
3. 切主题后同上，且新旧主题的 QSS 与字体都正确应用
4. 启动后默认选中并打开 App 扩展的应用页，不因扩展注册顺序漂移
5. Windows 任务栏显示 obox 图标，不再显示 python 图标
6. light 主题滑块轨道在页面底色上肉眼可辨，手柄与轨道对比清晰
7. 标题栏最小化、最大化、关闭三按钮在 light 与 dark 都有足够对比，悬停与关闭红底仍保留
8. 托盘菜单照豆包的分组式设计：白底圆角面板、三组之间细分隔线、行高约 44、无图标、14px 文字；三组为 打开 obox 窗口 ‖ 切换主题 / 切换语言 / 刷新扩展 / 打开扩展目录 ‖ 设置 / 退出
9. 主题与语言在托盘里用可勾选子菜单呈现当前值，菜单的悬停、文字与分隔线颜色跟随主题

## 关键取舍

- 版本号走新增 label 类型，而不是禁用输入框：只读项在视觉上不该长得像输入框，扩展也能复用
- 切换后恢复视图与分类，而不是重建后回首页：用户正在设置里改东西，跳走等于打断
- 任务栏图标用进程级 AppUserModelID + 窗口图标，而不是先打包 exe：源码运行也要正确，打包只是把同一图标写进 exe 资源
- 托盘菜单用 QMenu + 主题 QSS，不自绘：原生菜单的键盘与可访问性直接可用，观感靠 QSS 对齐豆包的分组留白与行高
- 中间组映射成宿主能力（切换主题 / 切换语言 / 刷新扩展 / 打开扩展目录），不为了像豆包而造业务功能；主题与语言用可勾选子菜单展示当前值
- 对比度用主题里的 TEXT / TEXT_MUTED 系取值，而不是硬编码灰色：两套主题才能各自达标

## 与基线的冲突

- 基线「设置贡献」只定义 bool、enum、string 三类条目，新增 label 属于扩展能力变化，需在 spec 里补一条
- 基线「运行中切换套件」只要求销毁重建视图，未要求保持当前视图；本次加保位，须 MODIFIED
- 基线「托盘常驻」只写常驻与关闭行为，没有规定菜单项与层级，菜单设计属 ADDED
- 基线未规定启动默认视图，本次固定为 App 应用页，属 ADDED
- 基线「托盘常驻」未规定菜单项与层级，本次按豆包分组式菜单重做，属 ADDED
- 基线「自绘标题栏」只写按钮存在与自绘，未给对比度要求；本次补可读性条款
