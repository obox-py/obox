# 扩展管理 Spec Delta

## Purpose

让扩展的安装、卸载与禁用能在 obox 运行中完成：新增系统扩展「扩展管理」提供安装按钮、搜索与卡片列表，宿主收消息后立刻激活或摘除扩展，各注册点与当前页当场刷新。

## ADDED Requirements

### Requirement: 扩展管理

obox SHALL 提供一个系统扩展（目录 extensions/management，清单 name=extensions、publisher=obox、version=1.0.0，扩展 id 为 extensions.obox），只注册一个 sidebar 视图 extensions.main，标题「扩展」。页面顶部是「安装扩展」主按钮，下面是搜索框与卡片列表：卡片显示名称、作者、版本、来源（内置 / 源码 / 用户安装）与状态（激活 / 失败 / 禁用）；用户安装的卡片额外提供卸载与禁用/启用，内置与源码扩展的卡片只读。安装按钮由扩展发出动作消息、由 obox 打开文件选择框并限定 .oix（扩展进程没有系统对话框能力），安装过程中按钮禁用；搜索按名称、作者、描述做不区分大小写的过滤，空搜索显示全部。

#### Scenario: 安装后立刻出现

- **WHEN** 在扩展管理页选择 gallery.obox.0.1.0.oix 并确认
- **THEN** 卡片列表立刻多出该扩展且状态为激活，侧栏与各注册点同时出现它的入口，页面提示安装成功

#### Scenario: 搜索过滤

- **WHEN** 在搜索框输入扩展作者 obox
- **THEN** 只显示作者匹配的卡片，清空后恢复全部

#### Scenario: 用户扩展可卸载

- **WHEN** 在用户安装的扩展卡片上点卸载，并在 obox 弹出的确认框里确认
- **THEN** 该扩展的视图与注册点消失，卡片从列表移除，安装目录被删除

#### Scenario: 系统扩展只读

- **WHEN** 查看内置或源码扩展的卡片
- **THEN** 卡片上没有卸载与禁用按钮

## MODIFIED Requirements

### Requirement: 扩展安装

改自基线「扩展安装」：安装不再只发生在启动时。

obox SHALL 支持启动时与运行中两种安装：启动时扫描安装目录下的 .oix 并解压；运行中由扩展管理页选中 .oix 后交给扩展宿主，宿主在运行中解压、校验并激活该扩展，然后把扩展、视图与命令列表回推给 obox，obox 增量挂载新视图而不重建整窗。同 id 的包按覆盖升级处理：先解压到临时目录，成功后再替换旧目录；任一步失败保留旧版本并回报原因。宿主 SHALL 支持运行中卸载用户安装的扩展：删除安装目录与它的存储目录、调用 deactivate 并摘除注册点。拒绝越出安装目录的压缩包成员这一条不变。

#### Scenario: 运行中安装

- **WHEN** 选中合法 .oix
- **THEN** 宿主解压到 .obox/extensions/{名称}.{作者}，激活扩展并回推状态，主窗口挂载它的视图

#### Scenario: 覆盖升级

- **WHEN** 安装与已装扩展同 id 的新版本
- **THEN** 目录被替换、扩展重新激活，卡片显示新版本

#### Scenario: 安装失败保留旧版

- **WHEN** 安装包清单缺作者或成员越界
- **THEN** 安装中止并回报原因，旧版本仍可用

### Requirement: 扩展生命周期与上下文注入

改自基线「扩展生命周期与上下文注入」：补运行中停用与卸载。

扩展宿主 SHALL 在激活时调用 activate 并注入 context，在停用或卸载时调用 deactivate 并摘除该扩展的视图、命令与应用注册；被禁用的扩展在激活阶段整体跳过，只在管理页显示为禁用状态。禁用只记名单、保留目录与存储；卸载删除用户安装目录与存储，且只对用户安装的扩展开放。

#### Scenario: 禁用即时生效

- **WHEN** 禁用某个用户安装的扩展
- **THEN** 它的视图与注册点立刻消失，卡片状态变为禁用，重启后仍不激活

#### Scenario: 启用恢复

- **WHEN** 重新启用该扩展
- **THEN** 它被重新激活，注册点恢复，卡片状态回到激活

### Requirement: 扩展目录与清单

改自基线「扩展目录与清单」：来源与启用状态要对管理页可见。

三个扩展根（安装目录的内置扩展、数据目录的用户安装、源码目录）SHALL 在扫描结果里带上来源标识，供管理页显示；禁用名单 SHALL 持久化在 .obox/config.json，宿主激活时跳过名单内的扩展。扩展 id 仍是「名称.作者」，同名冲突的优先级不变。

#### Scenario: 来源可见

- **WHEN** 打开扩展管理页
- **THEN** 内置扩展显示「内置」、.obox/extensions 下的显示「用户安装」、源码目录的显示「源码」

#### Scenario: 禁用名单持久化

- **WHEN** 禁用某扩展后重启 obox
- **THEN** 该扩展仍不激活，管理页仍显示为禁用

## Impact

- 宿主新增控制消息（安装、卸载、启用/禁用）与增量回推，双向协议要加消息类型
- .obox/config.json 增加禁用名单；卸载会删 .obox/extensions/{id} 与扩展存储目录
- 扩展管理是第三个系统扩展，侧栏多一个入口；安装/卸载会即时改变主窗口的视图集合
- 覆盖升级失败保留旧版；系统与源码扩展不可卸载、不可禁用
