# 扩展管理 · 系统扩展的安装、禁用与卸载

## 背景

现在装扩展只有两条路：把 .oix 丢进 .obox/extensions 等宿主启动时解压，或直接改 extensions/ 源码目录；装完必须重启才有反应，也没有一个能看清单、能装能卸的可视化入口。本次新增系统扩展「扩展管理」：顶部一个安装按钮（文件选择 .oix），下面搜索框与卡片列表，和 App 页的观感一致；安装、卸载、禁用都由扩展进程收消息后立刻处理，不重启 obox。

## 目标

- 系统扩展 extensions（作者 obox、版本 1.0.0）在侧栏提供「扩展」入口
- 安装按钮选 .oix 后，宿主立即解压并激活，注册点与当前页当场出现
- 全部已装扩展以卡片列出，支持按名称、作者、描述搜索
- 用户安装的扩展可卸载与禁用/启用；系统与源码扩展只读
- 卸载、禁用同样即时生效，禁用在重启后保持

## 范围

**做：**

- 新增扩展目录 extensions/management：extension.json、extension.py、views/main.oml、i18n.json、图标
- 宿主新增控制消息：安装、卸载、启用/禁用；处理后重新扫描并推送状态与视图
- obox 端增量应用宿主回推：挂载新视图、摘除卸载的视图、刷新应用页与设置页，不整窗重建
- 禁用到名单写入 .obox/config.json，宿主激活时跳过；卸载删除 .obox/extensions/{id} 与该扩展存储目录
- 安装对话框限定 .oix，失败给原因；同 id 覆盖升级
- 扩展管理页的卡片操作与状态刷新

**不做：**

- 不做扩展市场、远程下载、签名与完整性校验
- 不做版本历史与回滚（只做到失败时保留旧版本）
- 不做系统扩展（extensions/ 根内）的卸载与禁用
- 不改现有扩展的清单字段与打包格式

## 需求草案

1. 扩展管理是系统扩展：id 为 extensions.obox，只注册一个 sidebar 视图，标题「扩展」
2. 顶部「安装扩展」主按钮打开文件选择框，限定 .oix；安装中按钮禁用并显示进行中文案
3. 安装成功后目标扩展立刻激活，它的视图、应用与设置项在侧栏和各注册点出现，当前页卡片列表刷新并提示成功
4. 安装失败（非 zip、缺清单、清单字段缺失、成员越界、入口加载失败）给出原因，旧版本保持可用
5. 同 id 的 .oix 视为覆盖升级，替换目录后重新激活
6. 卡片列出全部已装扩展：名称、作者、版本、来源（内置 / 源码 / 用户安装）、状态（激活 / 失败 / 禁用）
7. 搜索框按名称、作者、描述做不区分大小写的过滤，空搜索显示全部
8. 用户安装的卡片提供卸载与禁用/启用；卸载删目录与存储，禁用只写名单并保留数据，两者即时生效
9. 系统与源码扩展的卡片只读，不出现卸载与禁用
10. 禁用名单持久化，重启后仍不激活

## 关键取舍

- 宿主收消息即装，不重启进程：安装后立刻在各注册点可见；代价是宿主要支持运行中加载模块，且 Python 无法真正卸载模块，禁用与卸载只能在注册表层面摘除
- 覆盖升级用「先解压到临时目录、成功后再替换」的语义，失败保留旧版本，避免半装状态
- 禁用不删目录与数据，只把 id 写进名单；卸载才删目录与存储，符合「禁用是临时状态、卸载是所有权转移」的划分
- 系统与源码扩展只读：它们随安装包或仓库分发，删掉会破坏安装，禁用会让系统页缺失
- 卡片复用 Flex + Card 的写法，与 App 页同构，不引入新的展示组件

## 与基线的冲突

- 基线「扩展安装」只描述启动时扫描 .oix；本次加入运行中安装与卸载，需 MODIFIED
- 基线「扩展生命周期与上下文注入」没有运行中停用与卸载的语义，需 MODIFIED
- 基线「扩展目录与清单」没有来源（内置/源码/用户）与禁用名单的概念，需 ADDED
- 基线「注册点」没有扩展管理的入口，需补一条
- 基线「设置扩展」与「App 扩展」的页面结构可复用，但扩展管理是并列的第三个系统扩展，需要一条新需求描述它
